# إعداد لوحة إدارة تياترو الصعيد

## رابط اللوحة
بعد دمج فرع التطوير ونشر الموقع على GitHub Pages:
`https://teatroalsaeed.org/admin-cms.html`

اللوحة في هذه المرحلة منفصلة عن لوحة إدارة فناني الصعيد، وتتصل فقط بمشروع Supabase:
`cusdjhfdhimoucjvxsmr`

## 1. إنشاء حساب مالك اللوحة
1. افتح [Supabase Authentication – Users](https://supabase.com/dashboard/project/cusdjhfdhimoucjvxsmr/auth/users).
2. اختر **Add user** ثم **Create new user**.
3. أدخل البريد الإلكتروني المخصص لإدارة تياترو، وأنشئ كلمة مرور قوية.
4. فعّل تأكيد البريد للحساب من شاشة الإنشاء إذا كان الخيار متاحًا.
5. لا تفعّل التسجيل العام للمستخدمين من إعدادات Auth؛ الحسابات الإدارية تُنشأ يدويًا فقط.

## 2. منح الحساب صلاحية المالك
افتح SQL Editor في مشروع Teatro AlSaeed، واستبدل البريد التجريبي في الاستعلام ببريد الحساب الذي أنشأته، ثم شغّل الاستعلام:

```sql
insert into public.admin_members (user_id, role)
select id, 'owner'
from auth.users
where lower(email) = lower('ADMIN_EMAIL@example.com')
on conflict (user_id) do update
set role = excluded.role
returning user_id, role;
```

يجب أن يعيد الاستعلام صفًا واحدًا. إذا لم يُرجع صفًا، راجع البريد وتأكد أن الحساب أُنشئ في مشروع Supabase الصحيح.

## 3. تسجيل الدخول
1. افتح `https://teatroalsaeed.org/admin-cms.html` بعد نشر الفرع.
2. سجّل الدخول بالبريد وكلمة المرور اللذين أنشأتهما.
3. إذا ظهر أن الحساب غير مصرح له، تأكد من وجود صفه في `admin_members`.
4. لا تشارك كلمة المرور مع فريق المحتوى. أنشئ لكل عضو حسابًا منفصلًا وأضفه إلى `admin_members` بدور `editor`.

## 4. الوظائف الموجودة
- الأخبار: العنوان والوصف العربي والإنجليزي، نص الخبر، الغلاف، المسودة والنشر.
- العروض: بيانات العرض والمخرج والسنة والبوستر والفيديو ومعرض الصور.
- دورات المهرجان: الشعار والوصف والمواعيد والمكان وصورة الغلاف.
- الفعاليات: ربط الفعالية بدورة وتحديد النوع والمواعيد والمكان.
- الورش: المدرب والمواعيد والوصف ورابط التسجيل.
- دعوات المشاركة: فترة التقديم ورابط الاستمارة والحالة.
- إعلانات التطبيق: نص الإعلان والرابط وموعد ظهوره.
- رفع صور JPG وPNG وWebP وAVIF حتى 10 ميجابايت إلى bucket `public-media`.

## 5. ملاحظات أمنية وتشغيلية
- الصفحة تستخدم Supabase publishable key فقط. لا يوجد service-role key أو secret داخل ملفات الموقع.
- صلاحيات القراءة والكتابة الفعلية يفرضها RLS في قاعدة البيانات، وليس إخفاء الأزرار في الواجهة.
- bucket الصور عام للقراءة، والرفع والتعديل والحذف محصور بالحسابات الموجودة في `admin_members`.
- دورا `owner` و`editor` مسجلان في قاعدة البيانات حاليًا، لكن التفريق التفصيلي بين صلاحياتهما لم يُفعّل بعد؛ كل عضو مُصرّح له يملك صلاحيات إدارة المحتوى الحالية.
- حذف السجل نهائي من قاعدة البيانات؛ تأكد من اختيار السجل الصحيح قبل التأكيد.
- لا تُعد هذه اللوحة بعدُ نظامًا كاملًا لإدارة أعضاء الفريق أو سجل تدقيق للتعديلات.
- صفحة الإدارة تستخدم `noindex,nofollow`، لكن هذا لا يغني عن تسجيل الدخول وسياسات RLS.

## 6. حدود المرحلة الحالية
اللوحة تحفظ البيانات في قاعدة Supabase المشتركة بين الموقع والتطبيق، لكن صفحات الموقع العامة الحالية لم تُحوّل بعد كلها لقراءة المحتوى من قاعدة البيانات. يلزم تنفيذ ربط الواجهة العامة وترحيل الأرشيف والتحقق من الروابط قبل اعتمادها كمصدر موحد بالكامل.
