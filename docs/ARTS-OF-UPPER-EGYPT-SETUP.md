# منصة فنون الصعيد — إعداد النسخة الأولى

## ما أُضيف
- `artists.html`: واجهة عربية/إنجليزية للدليل واستمارة التقديم.
- `supabase/artist-directory-schema.sql`: مخطط أولي للطلبات وسياسات الوصول.
- لا توجد بيانات فنانين تجريبية منشورة، ولا يتم حفظ أو إرسال بيانات النموذج قبل الإعداد.

## مطلوب قبل الإطلاق
1. إنشاء مشروع Supabase تحت حساب تياترو الصعيد.
2. مراجعة وتشغيل ملف SQL من Supabase SQL Editor.
3. إنشاء bucket خاص باسم `artist-submissions` مع حد 5MB وقصر الأنواع على PDF وJPG/PNG/WEBP. إعداد سياسات رفع آمنة؛ الملفات والسير الذاتية تظل خاصة حتى مراجعتها.
4. إعداد آلية إدارة محمية (Supabase Auth) لمراجعة الطلبات. إضافة حسابات الفريق إلى `artist_directory_admins` من لوحة SQL بعد إنشاء المستخدمين. لا تضف صلاحيات الإدارة إلى واجهة عامة.
5. ربط الواجهة بمشروع Supabase باستخدام publishable key فقط، مع تفعيل RLS واختبار صلاحيات الرفع والقراءة. **ممنوع وضع service-role/secret key في ملفات الموقع.**
6. بناء صفحة عرض الملفات المعتمدة من قاعدة البيانات وصفحات الفنانين المستقلة، مع عدم نشر البريد أو الملفات الخاصة تلقائيًا.
7. اختبار الاستمارة والرفع والمراجعة والحذف على نسخة تجريبية قبل الإعلان العام.

## مسارات مقترحة
- `/artists` — الدليل والتقديم.
- `/artists/slug` — ملف الفنان بعد اعتماد النشر (مرحلة لاحقة).
- `/admin/artists` — مراجعة الطلبات، خلف تسجيل دخول وصلاحيات إدارية.

## نقطة مهمة
الواجهة الحالية Prototype: الاستمارة لا ترسل أو تحفظ أي بيانات عمدًا إلى أن تُعدّ خدمة خارجية ويُختبر تأمينها. لا تعلن فتح التقديم حتى اكتمال الخطوات أعلاه.
